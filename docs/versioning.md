# 版本与提交规范

## 应用版本

前后端独立版本，均使用语义化版本 `主版本.次版本.修订版本`：

- `frontend/package.json` 与 `frontend/CHANGELOG.md` 管理网站版本。
- `backend/pom.xml` 与 `backend/CHANGELOG.md` 管理 API 版本。
- 不相关的前后端变更不需要同步递增另一个应用的版本。
- 破坏兼容的 API 或应用行为变更递增主版本；向后兼容的业务能力递增次版本；兼容性修正递增修订版本。

## 发布标签

标签按应用隔离，格式为 `frontend/vX.Y.Z` 和 `backend/vX.Y.Z`。一次发布只为实际发布的应用创建标签。跨前后端的整体部署可额外建立 `release/vX.Y.Z` 标签，并在发布记录中列出对应应用版本。

## 中文提交信息

提交信息统一使用中文，格式为：

```text
<类型>(<业务>): <简洁明确的中文描述>
```

业务范围使用 `web`、`api`、`docs`、`build` 或 `repo`。类型使用：

- `feat`：新增用户可见能力
- `fix`：修正错误行为
- `refactor`：调整结构且不改变预期行为
- `perf`：性能改进
- `test`：测试调整
- `docs`：文档变更
- `build`：依赖、构建或部署配置
- `chore`：其他维护工作

描述使用动宾短语，说明结果，不加句号，不用“修改代码”“优化一下”等含糊文字。示例：

```text
feat(web): 首页搜索跳转到文章检索页
fix(api): 公告为空时返回空值
refactor(repo): 按前后端业务拆分单仓目录
docs(repo): 补充中文提交与独立发版规范
```

## 变更记录

每个应用的 `CHANGELOG.md` 按版本记录新增、修复、调整和移除项。发布前更新对应应用版本、变更记录并创建应用标签。
