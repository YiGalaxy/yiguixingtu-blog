# 版本与提交规范

## 仓库和应用

前端 `frontend/` 与后端 `backend/` 由同一 Git 仓库管理，不分别初始化仓库。
应用使用 SemVer `主版本.次版本.修订版本`，分别在 `frontend/package.json`、`backend/pom.xml` 和各自 `CHANGELOG.md` 中记录。接口破坏兼容递增主版本，新增业务能力递增次版本，兼容性修正递增修订版本。

## 按业务管理版本

跨前后端的业务作为一个交付单元，在 [业务版本记录](业务版本记录.md) 中记录业务版本、涉及的应用版本和验收结果。业务版本与应用版本独立；同一业务涉及前后端时放在同一条业务记录中。

| 业务范围 | 内容 | 发布标签前缀 |
|---|---|---|
| 文章阅读 | 首页、检索、分页、阅读、目录 | `business/reading/vX.Y.Z` |
| 内容发布 | 管理员编辑、草稿、分类、标签、图片、附件 | `business/publishing/vX.Y.Z` |
| 评论互动 | 游客留言、审核、邮箱隐私 | `business/comments/vX.Y.Z` |
| 站点展示 | 昼夜主题、导航、关于、项目、收藏、友链、设置 | `business/presentation/vX.Y.Z` |
| 媒体存储 | 上传、读取、文件引用保护与清理 | `business/media/vX.Y.Z` |
| 访问统计 | 页面上报、访问趋势、访客构成、排行和 IP 明细 | `business/analytics/vX.Y.Z` |
| 数据迁移 | 导入、校验、备份和恢复 | `business/migration/vX.Y.Z` |

业务正式验收发布时创建对应标签；本地预览完成不等于线上发布，不预建发布标签。应用发布可同时创建 `frontend/vX.Y.Z`、`backend/vX.Y.Z`；整体部署记录列出本次包含的业务与应用版本。

## 中文提交信息

格式：`<类型>(<业务>): <中文动宾短语>`。业务范围采用上表中文名称，也可使用明确的业务名，例如“管理员认证”。不要用 `web`、`api`、`repo` 代替业务范围。

类型使用 `feat`（新增）、`fix`（修正）、`refactor`（重构）、`perf`（性能）、`test`（测试）、`docs`（文档）、`build`（构建）、`chore`（维护）。描述说明业务结果，不用“修改代码”“优化一下”等含糊表述。

新项目首次建立业务时，以新开发方式描述：

```text
feat(文章阅读): 建立文章筛选分页与 Markdown 阅读体验
feat(内容发布): 建立正文插图与文章附件发布流程
feat(站点展示): 建立像素主题与个人展示页面
```

后续实际修复才使用 `fix`，历史提交保留，不为改变表述重写既有历史。每次业务交付同步更新业务记录；应用发版同步更新版本号及变更记录。
