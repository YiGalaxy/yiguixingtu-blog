## 发布中处理的问题

首次准备过程中，新旧应用并行启动造成内存压力，主机响应中断，经用户在云控制台重启恢复。重启后改为停止新容器、停止旧后端、备份并校验、启动新后端并等待就绪、迁移、启动新前端、切换 Nginx，最后停止旧前端。

首次正式迁移因旧文章 NULL 正文与新库非空约束冲突而失败，事务未提交，脚本自动停新并恢复旧站。补充空正文兼容后，在真实数据库事务内执行迁移并强制回滚进行预检，成功后再次制作备份并正式迁移。重试备份使用新的时间目录，旧备份保留。
